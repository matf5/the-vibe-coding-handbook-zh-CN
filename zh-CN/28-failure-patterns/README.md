# 失败模式：AI 辅助开发中出了什么问题

## 代码质量问题

### 模式 1：静默 Bug
AI 会生成看似合理实则错误的代码。
**修复方法**：接受代码前务必先写测试。

### 模式 2：风格不一致
不同会话会产生不同的模式。
**修复方法**：编写风格指南提示词，使用 linter。

### 模式 3：过度工程
简单的解决方案变得不必要地复杂。
**修复方法**：在提示词中写上"保持简单"。

## 安全漏洞

### 模式 4：注入漏洞
生成的代码中存在 SQL 注入、XSS。
**修复方法**："按照 OWASP 指南编写安全代码。"

### 模式 5：硬编码密钥
源代码中出现 API 密钥和密码。
**修复方法**：切勿在提示词中分享密钥，使用环境变量。

### 模式 6：认证失效
身份验证实现薄弱。
**修复方法**：使用成熟的库，并请专家审查。

## 流程失败

### 模式 7：没有测试
未经测试就发布 AI 代码。
**修复方法**：测试是强制要求，不是可选项。

### 模式 8：跳过审查
直接提交 AI 生成的代码。
**修复方法**：所有代码都需要人工审查。

### 模式 9：没有文档
代码能跑，但没人能看懂。
**修复方法**：在每个提示词中都加上"添加文档"。

## 团队动态

### 模式 10：技能退化
开发者丧失了基本功。
**平衡之道**：定期进行不用 AI 的编码练习。

### 模式 11：知识孤岛
只有一个人懂那些提示词。
**修复方法**：共享提示词库，分享知识。

## 预防策略

### 技术层面
- 自动化测试（CI/CD）
- 静态分析（linter、安全扫描）
- 强制代码审查

### 流程层面
- 完成标准包括测试 + 文档
- 每月代码质量审计
- 每周提示词分享会

### 文化层面
- 承认错误时的心理安全感
- 人人对质量负责
- 把 AI 当作工具，而非拐杖

---

**目标**：增强智能，而非人工替代。
