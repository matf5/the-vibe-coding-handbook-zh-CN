## 🎯 为什么自我评估重要

Sonar 2026 年的调查发现，**96% 的开发者并不完全信任 AI 生成的代码**，但只有 48% 的人会在提交前每次都检查它。“使用 AI”与“安全地使用 AI”之间的差距，正是自我评估发挥作用的地方。

自我评估迫使你直面自己真正理解的东西，与智能体为你产出的东西之间的差别。用下面的量表诚实地给自己打分，然后沿着认证路径补齐短板。

## 🏆 Vibe Coding 综合就绪分数

诚实回答以下五个问题：

1. **不问智能体，我能讲清楚自己 AI 生成的代码是如何工作的吗？**（是 / 否）
2. **每次部署 AI 生成的代码之前，我都会运行测试和安全扫描吗？**（是 / 否）
3. **我知道自己每月的 AI token 支出，以及每类任务在用哪个模型档位吗？**（是 / 否）
4. **我能用一条命令回滚一次智能体生成的生产变更吗？**（是 / 否）
5. **每个 AI 生成的组件都有具名的人类负责人吗？**（是 / 否）

**分数：** 5/5 = 已具备生产就绪水平 · 3–4 分 = 接近了，收紧护栏 · 0–2 分 = 暂时不要把 AI 生成的代码部署到生产环境

## 🎓 认证路径

按顺序完成各级别。每个级别都有前置条件、需要展示的技能和一项顶点任务。

---

### 第 1 级——AI 辅助构建者

**前置条件：** 无

**需要展示的技能：**
- [ ] 选择并配置一款 AI 编程工具（Cursor、Copilot 或 Claude Code）
- [ ] 用“意图重于实现”的方式编写有效的提示词
- [ ] 在接受智能体生成的代码之前，先阅读并理解它
- [ ] 在 AI 生成的代码中运行测试并修复 Bug
- [ ] 将一个简单的应用部署到托管平台（Vercel、Railway 或类似平台）

**顶点任务：** 仅使用 AI 辅助，构建并部署一个小型全栈应用（例如带认证的待办清单），测试与安全扫描均通过。

**认证方式：** 自我认证——把你的应用、所用工具和经验教训记录成一篇案例研究（提交到第 34 节）。

---

### 第 2 级——AI 原生开发者

**前置条件：** 完成第 1 级

**需要展示的技能：**
- [ ] 将 IDE 助手（Cursor/Copilot）与终端智能体（Claude Code/Codex）配对使用
- [ ] 使用第 30 节的工作流编写规格（用户故事 → 计划 → 任务 → 验证）
- [ ] 为项目配置 `AGENTS.md` 和 `CLAUDE.md`
- [ ] 强制执行模型路由（难题用旗舰模型，常规任务用超值档位）
- [ ] 跟踪 token 支出并应用成本控制（第 31 节）
- [ ] 强制执行智能体安全控制（检查点、支出上限、沙箱）

**顶点任务：** 使用智能体重构一个现有代码库，把工作拆成多个小 PR，每个 PR 都有人工评审、测试和安全扫描。记录重构前后的指标。

**认证方式：** 自我认证，提供展示了经评审、测试的智能体工作的 PR 历史。

---

### 第 3 级——AI 系统工程师

**前置条件：** 完成第 2 级

**需要展示的技能：**
- [ ] 用经安全评审的 Dockerfile 将 AI 生成的应用容器化
- [ ] 部署到 Kubernetes，配置清单、HPA，并测试回滚
- [ ] 强制执行企业护栏（扫描每个 PR、最小权限智能体、密钥保护）
- [ ] 为 AI 生成的组件指派负责人并安排维护预算
- [ ] 记录合规映射（SOC 2、GDPR、HIPAA、PCI、EU AI Act，视适用情况而定）
- [ ] 带领团队完成一次与智能体相关的故障响应

**顶点任务：** 将一个 AI 构建的多服务应用部署到 Kubernetes，配备监控、告警、特性开关和经过测试的回滚流程，并进行一次故障演练。

**认证方式：** 自我认证，提供架构图、部署清单和故障演练记录。

## 📝 如何使用本路径

1. **先做自我评估**——找出自己的薄弱章节
2. **学习这些章节**——完成其中的练习和示例
3. **完成第 1 级顶点任务**——交付一个小而完整的项目
4. **进阶到第 2 级**——加入规格、智能体和成本控制
5. **达到第 3 级**——生产级 Kubernetes、治理与故障响应
6. **贡献一篇案例研究**——分享你的收获（第 34 节）

你不必完成所有级别。在目标需要的地方停下即可。

## 🔑 要点总结

- **诚实的自我评估能弥合“使用 AI”与“安全地使用 AI”之间的差距**
- **三个认证级别：** 构建者 → 原生开发者 → 系统工程师
- **每个级别都有一项顶点任务**——交付真实的东西来完成认证
- **贡献案例研究**，帮助社区从你的经验中学习
- **认证按自己的节奏进行**——在目标需要的地方停下
