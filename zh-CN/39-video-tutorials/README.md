## 🎯 视频对氛围编程为何重要

读一份规格或 README 是一回事；看一位有经验的构建者指挥智能体、评审输出、发现 Bug 并修复它，是另一回事。视频记录了氛围编程的**隐性知识**：

- 智能体理解错时，如何措辞提示词
- 何时接受一次编辑、何时拒绝
- 如何快速阅读智能体生成的代码
- 一次好的（和一次差的）智能体会话是什么样子

**原则：** 绝不要只照抄视频里的内容。暂停下来，阅读生成的代码，理解之后再运行它。

## 1️⃣ 第 1 级演示——第一步

**主题：“我的第一个 AI 生成应用”**

在一次会话中构建并部署一个简单的全栈应用（带认证的待办清单）：

1. **选择技术栈**——Next.js + Tailwind + Supabase（或你偏好的组合）
2. **提示智能体**——“创建一个带用户认证、任务创建和完成切换功能的待办应用”
3. **评审输出**——阅读认证流程、数据库表结构和路由处理函数
4. **编写测试**——在部署前为关键路径添加测试
5. **安全扫描**——运行 SAST 和密钥扫描
6. **部署**——一键部署到 Vercel 或类似平台

**看视频时要注意：**
- 创作者如何措辞最初的提示词
- 他们是阅读了生成的代码，还是直接接受
- 他们如何处理错误和智能体的失误
- 部署命令以及所需的配置

## 2️⃣ 第 2 级演示——智能体工作流

**主题：“用 Claude Code + Cursor 做规格驱动重构”**

展示 2026 年的制胜模式：

1. **编写规格**——用户故事、验收标准、约束条件
2. **拆成任务**——小而可评审的单元
3. **Cursor 做日常编辑**——功能开发、UI 细节调整
4. **Claude Code 做重活**——多文件重构、迁移
5. **小 PR**——每个 PR 一个功能，每个 PR 都有人工评审
6. **跟踪成本**——每次会话的 token 支出、模型路由

**主题：“模型路由实践”**

展示何时使用每个档位：
- 旗舰模型（Opus 5.5 / Astra / Argon）——困难的多文件工作
- 中端模型（Sonnet 5.5 / Sol）——日常编程
- 超值档位（Haiku / Luna / Terra）——重复性、高频步骤

## 3️⃣ 第 3 级演示——生产与 K8s

**主题：“把 AI 构建的应用部署到 Kubernetes”**

端到端的生产部署：

1. **容器化**——编写并评审 Dockerfile（非 root、无密钥）
2. **K8s 清单**——Deployment、Service、HPA、探针
3. **金丝雀发布**——先部署到 10% 流量，监控，再扩大或回滚
4. **监控**——错误率、延迟、Pod 重启
5. **回滚演练**——故意破坏一次发布，然后执行 `kubectl rollout undo`

**主题：“AI 相关故障响应”**

模拟并应对：
- 凭证通过智能体上下文泄露
- 未经评审的智能体 PR 引入 Bug
- 失控的智能体会话烧掉 token

## 🧠 如何有效使用视频教程

| 应该做 | 不要做 |
|----|-------|
| 暂停并阅读生成的每一行代码 | 不阅读就复制粘贴 |
| 跟着写，然后自己修改项目 | 一模一样地照做，不做实验 |
| 记录智能体的失误与修复方法 | 以为视频展示的就是最佳实践 |
| 自己测试部署好的应用 | 轻信“视频里能跑就行” |
| 对你构建的东西运行安全扫描 | 因为视频没展示就跳过测试 |

**20 分钟规则：** 如果一个视频承诺 20 分钟建成一个应用，预计要花 2–3 小时评审、测试并加固它，它才能达到生产就绪水平。

## 🎥 制作你自己的演示

手册欢迎社区贡献的视频演示。贡献方式：

1. **选一个主题**，从推荐列表中选或自己提议
2. **录制屏幕**，记录你用 AI 构建的过程（Loom、OBS 或类似工具）
3. **讲解你的决策**——为什么这样提示、为什么接受或拒绝编辑
4. **展示评审过程**——测试、安全扫描、部署、回滚
5. **上传并附上链接**——托管在 YouTube/Vimeo，向 `39-video-tutorials/` 提交 PR，附上链接和摘要

**我们看重的是：**
- 诚实的失误与恢复（而不只是完美的演示）
- 明确的安全与测试步骤
- 对智能体行为的清晰讲解
- 已匿名的仓库（没有真实凭证或公司数据）

## 🔑 要点总结

- **视频展示隐性知识**——提示、评审、修复——这是文字无法传达的
- **不阅读就不要复制粘贴**——即使是受信任的创作者
- **预计要花视频时长的 2–3 倍**做评审、测试和安全工作
- **欢迎社区演示**——展示你的失误，而不只是成功
- **用视频学习，然后自己构建**——不要依赖教程
